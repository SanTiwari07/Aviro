## Hackathon Context

This project was built for the **Razorpay AI Buildathon 2026** (Track 04 — *AI Finance Controller*).

## Integration Status

| Item | Status | Details |
|---|---|---|
| Direct Razorpay Payment Gateway API | **Not Integrated** | Reconciliation occurs post-transaction using data extracts |
| Razorpay Webhook Ingestion | **Not Integrated** | Offline/batch CSV ingestion is used |
| Razorpay Settlement Recon Schema | **Supported** | Settlement formats follow Razorpay standard settlement exports |

## Why Direct Payment APIs are Not Implemented

Arivo functions as a **post-clearing financial controller**, reconciling downstream records after financial events have occurred. In real-world enterprise finance departments:
1. Core payment transactions are processed at runtime by customer-facing checkout services.
2. At end-of-day (T+1/T+2), settlement batches and payout reports are exported from payment gateways (Razorpay, Stripe, Adyen) and bank partner files.
3. The Finance Controller ingests these reports to verify that funds credited to the bank match captured payments minus contractual deductions (fees, GST, chargebacks).

Therefore, Arivo intentionally avoids triggering payment collections, refunds, or direct monetary transfers via client-side or server-side Razorpay APIs.

## Data Model Compatibility

The synthetic dataset generated by `dataset/generate_dataset.py` is modelled on Razorpay's data structures:
- `payment_id`: Matches Razorpay payment ID format (e.g. `pay_...` or synthetic `PAY_...`).
- `settlement_id`: Mirrors Razorpay settlement batches (`setl_...` or synthetic `SET_...`).
- `settlement waterfall`: Gross amount minus fees, tax, refunds, and adjustments matching standard Razorpay settlement calculations:
  $$\text{Net Amount} = \text{Gross} - \text{Fees} - \text{Tax} - \text{Refunds} - \text{Chargebacks} + \text{Adjustments}$$

## Roadmap: Adding Live Razorpay API Integration

If integrating live Razorpay APIs in the future:
1. **Server-side only**: Store `RAZORPAY_KEY_ID` and `RAZORPAY_KEY_SECRET` in `.env`. Never expose secrets to Vite/frontend.
2. **Settlements API**: Use `GET https://api.razorpay.com/v1/settlements` to poll settlement batches automatically.
3. **Recon API**: Fetch combined transaction settlement reports via Razorpay's Settlement Reconciliation endpoints.
4. **Webhook Verification**: Validate `X-Razorpay-Signature` with HMAC SHA256 before accepting event payloads.
